AI Agent 速成

读图约 50 秒 · 自适应测验 2–7 题
Core Fact · 先纠一个普遍误解

Agent 不是「更会聊天的模型」，
而是能自己动手完成任务的应用

模型只会「说」，Agent 会「做」：LLM 当大脑做规划，工具当手脚连接外部世界，在「思考 → 行动 → 观察」的循环里自主推进，直到把目标做完。

本质一个应用 三件套模型 · 工具 · 编排层 分水岭自主决策 + 调用工具
01

Agent 的内部构造

ai-agent/ ← 一个能自主做事的应用 ├── model 必需 │ └── LLM：推理 · 规划 · 决策 ├── tools 必需 │ └── API/搜索/代码：连接外部世界 ├── orchestration 必需 │ └── 主持循环：维护记忆与状态 │ └── 思考→行动→观察→再思考 └── stop condition └── 目标达成 / 最大步数 才停下
模型 model = 大脑

大语言模型负责理解任务、拆解步骤、决定「下一步做什么」。

工具 tools = 手脚

搜索、API、执行代码……模型靠它获取实时信息并真正改变外部世界。

编排层 orchestration = 神经

驱动「思考→行动→观察」循环，管理记忆与状态，直到目标达成或触发停止条件。

02

别混淆：与聊天 AI、Workflow 的区别

聊天 AI vs Agent

聊天 AI 是「有问有答」：单次生成回复，一般不调工具、不改世界。Agent 带着目标自己规划多步、调用工具执行，把「聊天」变成「办事」。

Workflow vs Agent

两者同属「智能体类系统(agentic)」，真正的分界是流程控制权：Workflow 由预定义代码路径编排（像有轨列车）；Agent 由 LLM 动态引导流程与工具使用（像自动驾驶）。

两条原则（Anthropic）

原则一：别轻易造 Agent

从最简单的方案开始：单次 LLM 调用 + 检索 + 示例往往已够用；固定、可预测的任务用 Workflow 更稳更省。Agent 自主性高，但代价是更高成本与错误累积风险——先在沙盒中充分测试并配好护栏。

原则二：打磨 Agent 三要诀

简单 —— 用可组合的小模式
透明 —— 展示它的规划步骤
打磨工具 —— 文档清晰 + 充分测试
