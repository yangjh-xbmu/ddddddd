Core Fact · 先纠一个普遍误解

它们不是同类东西：
Skill 管"会不会" · 插件管"接不接" · MCP 管"怎么统一接"

一句话分清：Skill 是"方法论"（教 AI 怎么把事做专业），插件/外部工具是"能力"（让 AI 能操作真实系统），MCP 是让这些工具接入 AI 的"标准化协议"。

02

易错点与协同

误区 A · Skill 是单个文件？

不是。Skill 是一个文件夹（目录），目录里必需 SKILL.md，可配 scripts/、references/、assets/。

误区 B · Skill 只"讲道理"不碰工具？

不是。官方文档称 Skill 封装脚本与工作流，在授权下也能调用第三方 API —— 但它的本分仍是教"怎么做"。

正解：Skill 与 MCP 互补而非对立

Skills 提供"执行方法论"（如何完成任务），MCP 提供"工具能力"（可以调用哪些外部工具），两者可同时使用 —— 一个 Skill 可以指导 AI 通过 MCP 连上的数据库工具完成查询。

03

使用前注意

装第三方 Skill 前先审计：网络下载的技能包可能夹带风险脚本，安装前分级把关 —— P0 危险别装 / P1 谨慎确认 / P2 安全可装。

插件/MCP 涉及授权：接入外部系统前先核对权限申请与数据外发范围，用小范围验证后再放大使用。
