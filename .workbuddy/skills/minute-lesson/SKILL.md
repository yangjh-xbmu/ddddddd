# Minute Lesson · 一分钟速成学习页

把一个知识点浓缩成一张"约 90 秒读完 + 闯关自测"的单文件 HTML 学习页。

## 何时使用

- 用户想快速学会某个知识点/概念/工具/功能，希望拿到一份精炼的学习材料
- 用户要求"一分钟掌握 X""做 X 的速成卡""带测试题的学习页"
- 为课程/课件制作轻量速学素材（适合教师与自学场景）

## 图示分工（重要）：本 skill 只画轻量示意图，重型图移交 archify

用户级技能 **archify**（`~/.workbuddy/skills/archify`）已安装为独立制图引擎：由自然语言或 Mermaid 生成**校验过的可交互独立 HTML 图页**（架构/流程/时序/数据流/生命周期五类，含主题切换、导出、确定性校验管线 validate→deliver）。

- **学习页内的装饰性小图**（目录树、对比卡、2-4 节点流程小图、记忆口诀）→ 仍由本 skill 直接产出，遵循 `references/design-rules.md`（极简单主色、无动画）。
- **知识点本身是"系统架构 / 多步流程 / 时序链路"且用户希望得到可交互总览图** → 改用 archify：按它的 JSON 规范创作→`validate`→`deliver` 出独立 HTML 图页，再在本学习页中以 `<a>` 链接或 iframe 外链该图页，正文只放少字要点。
- 判定口诀：`图是不是学习页的一部分 → minute-lesson；图是不是独立交付物 → archify`。

## 工作流（按序执行，勿跳过）

### Step 1 · 先查证，再动笔（强制）

禁止凭模型记忆直接输出知识点内容。必须先完成查证并记录来源：

1. 若知识点与某产品/框架/平台相关：用 WebFetch 读取其**官方文档**；WebFetch 输出不完整时改用 WebSearch 定位权威页面后再抓取。
2. 若本机装有相关官方技能（如 skill-creator、tencent-docs 等），优先读取其 SKILL.md 作为权威依据。
3. 提炼「核心事实」时，特别标出**最常见误解**（教学价值最高，例如 Skill 是"目录"而非"单个文件"）。
4. 汇总来源清单：`{ 标题, URL, 依据哪一句 }`，URL 必须是真实可点击的，随产出物一并交付。

### Step 2 · 定结构与难度分层

按 `references/design-rules.md` 的「页面骨架」组织内容（约 5 个小节、少字大图）。

设计测验题库时完成三层难度划分：
- **初学(1) / 进阶(2) / 熟练(3)** 各 ≥3 题；每题含：题干、4 选项、正确项、一句解析。
- 面向易错点出题：第 1 题优先考"最常见误解"。

### Step 3 · 生成单文件 HTML

- 文件名：`<主题短名>-in-one-minute.html`，落在当前工作区（无特殊要求时）。
- 全部视觉/交互规范见 `references/design-rules.md`（单主色极简、无 emoji、一题一屏等），照抄其中 CSS 变量与结构，不要自创风格。
- 测验交互必须是**自适应分层**：从中级(2)起步；**答对升一档、答错降一档**；规则与结束条件见 design-rules.md 的「分层自适应测验」，直接嵌入其 JS 骨架。
- 页面**必须**包含「资料来源」区（页脚上方）：列出 Step 1 收集的来源标题与真实链接；若知识点存在"官方教程/文档首页"，置于首位。页面标题栏或结尾注明"内容依据官方文档编写"。

### Step 4 · 交付

1. 用 present_files 打开生成的 HTML 预览。
2. 把「产出物路径 + 主题 + 来源清单」追加写入当日 memory 日志：`.workbuddy/memory/YYYY-MM-DD.md`。
3. 若用户未指定知识点而本流程产出了新规范经验，同步回写本 skill（积累 · 反思 · 修正）。

## 质量红线

- 无任何来源链接 → 视为未完成，返回 Step 1。
- 知识点描述与权威来源冲突 → 以来源为准。
- 配色/图标超出 design-rules 约束 → 重做视觉。
- 测验不是分层自适应 → 视为未完成。
