# Karpathy 谈 LLM Wiki：让知识自己长出来

> 来源：某播客节目摘要，2026-04-12。整理自 Andrej Karpathy 的一次访谈片段。

最近一直在做一个小实验：把读过的论文、笔记、网页统统扔进一个 `raw/` 文件夹，
不整理、不改格式。然后让模型去读它们，把里面的概念提炼成一个个互相关联的
markdown 页面，放到 `wiki/` 里。

几个月下来，效果出乎意料。大概攒了 100 来篇文章、四十万词左右，整个库居然还
是很好查——不需要向量数据库，不需要 embeddings，模型顺着目录、索引页和互链
就能找到东西，像人查资料一样。

为什么不用 RAG 这种检索增强生成？我的判断是：RAG 每次提问都要重新检索、重新
推导一遍答案，本质上没有积累。而 LLM Wiki 是"编译一次，持续更新"。新的文章
进来之后，概念页会被改写、交叉引用会补上、和已有内容的矛盾会被当场标出来。
时间越久，库越厚，而且质量在上升而不是在腐烂。

我最看重的是"健康检查"这一步。每隔一阵让模型把整个库扫一遍：哪些页面互相矛盾、
哪些地方有缺口、哪些旧结论已经被新证据推翻了。这一步让知识库从"只进不出"的
仓库变成了会被主动维护的活系统。

我的态度很明确：这套东西值得长期投入。它不像 RAG pipeline 那样一旦语料变多就
开始发皱，它是复利型的——你投的每一篇材料都在抬高整个库的天花板。对个人研究
者、独立开发者这种没有大团队的人，我认为这是目前性价比最高的知识管理方式。
