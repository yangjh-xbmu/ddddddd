# 我为什么放弃了那个 LLM 知识库（一篇劝退文）

前同事上个月跟我聊他那个折腾了一年的 AI 知识库，我听完劝他停掉。理由如下，
也是我自己去年踩坑后的结论。

把"让 AI 自动维护一个 wiki"当成日常习惯，问题比看上去大得多：

1. **维护成本是隐性的。** 每 ingest 一篇材料，模型都要读全文、改概念页、补交叉
   引用、更新总览。看着是自动的，实际上你在为每一次操作付费（token）或者等待
   （本地模型跑一篇长文要十几分钟）。库越大，单次 ingest 越慢、越贵。
2. **"复利"的前提是你会一直查。** 我的知识库一年里被认真查询的次数不超过
   二十次，而 ingest 了几百篇。投入和收益完全不成比例。真正高频被查的笔记
   不到 10%，剩下的是在吃灰。
3. **自动改写会引入漂移。** 概念页被模型改写一次是润色，改写十次就成了改写者
   的"观点融合"，你分不清哪句是你当年写的、哪句是模型脑补的。溯源变成了一件
   很烦的事。

我不是说"结构化的互链知识库"这个想法有问题——Karpathy 那套两文件夹模式本身
挺优雅。我的说法是：**对大多数人来说，它不值得当成日常基础设施来养。**
把时间花在"需要查的时候现查"或者"用更轻的标签系统"上，回报更高。一句话：
别为了维护知识库而活，要为了用知识库而活。
